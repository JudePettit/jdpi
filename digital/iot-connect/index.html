IoT Connect

Switch, dim, colour, play, pause and turn up or down your own smart devices from one page: bulbs, speakers, TVs and the EZCast receiver. The page talks to the Vitruvian Manager bridge on your computer, where Hermes Messenger finds your devices, says how their makers connect them and can publish them to your own MQTT broker.

The Vitruvian Manager bridge

Download prp-bridge.mjs

  1. Install Node.js 22 or newer and download the bridge (version 2.0.0 or later).
  2. Write its config file once (below), naming your home connection as Windows names it (for example Wi-Fi), and start it from a terminal, so that it can ask you Y or N: 
    node prp-bridge.mjs --iot --config vm-bridge.json
  3. When Windows asks, allow Node.js on Private networks only, never Public ones.
  4. Turn on Off
  5. The first time, Chrome and Edge ask to let this site reach apps on this device. Allow it for the bridge; you can withdraw it in the site settings.

The page contacts the bridge only once you turn it on or press Check. Without --iot the bridge answers the SIGINT Dashboard as before and IoT Connect stays off.

The config file (vm-bridge.json) 
{ "port": 8790, "iot": { "enabled": true, "origins": [], "interface": "Wi-Fi",
  "state": "C:/Users/<you>/AppData/Roaming/VM/bridge/iot-state.json",
  "lan": { "enabled": false, "address": "192.168.1.20", "port": 8791 },
  "homeAssistant": { "url": "http://homeassistant.local:8123" },
  "broker": { "url": "ws://192.168.1.20:9001", "username": "vm", "site": "home", "json": true,
    "sparkplug": false, "group": "VM", "edgeNode": "hermes", "acceptCommands": false },
  "ai": { "enabled": false } } }

Leave out what you do not run: without homeAssistant or broker those routes stay off. The page can change none of this: only you can, in the file. Passwords and tokens never go in it: the broker's password is VM_MQTT_PASSWORD in the bridge's environment.

What it drives

  • Players: the EZCast U02 and other DLNA players, and Sonos: play an address, pause, stop, set volume.
  • Lights: Philips Hue, LIFX, WiZ and Yeelight: switch, dim and colour.
  • Switches: Shelly (second generation and later) and Tasmota.
  • TVs: Roku, LG webOS and Samsung Tizen: the remote's keys, volume and power.
  • Everything else through your own Home Assistant, including a Broadlink infrared blaster.
  • A unified namespace: each device's state on your MQTT broker as plain JSON, and as a Sparkplug B node if you switch it on.
  • Your phone as the remote, on your own Wi-Fi.

What it does not do

      Hermes Messenger

      Not checked

      Hermes Messenger is a preconfigured process inside the bridge, not a service on the internet. It works by fixed rules: it identifies what answered the standard discovery questions, explains how its maker says to connect it, does the documented step when you click and press Y, checking it with one harmless read, and reports each finding as a message the Integration Hub can read. An AI is optional and never in charge.

      Findings

        Ask an AI about an unknown device

        Off

        It sends only the maker, the model, the device type, the service types and the server's product token, never a name, a room or an address. Its answer shows as “AI suggestion, not checked” and never becomes a command.

        A unified namespace for the house

        A unified namespace (UNS) is one live, shared directory of everything in the house, kept on an MQTT broker that you run. The bridge holds one connection to it, set in its config file (iot.broker), and publishes each device's state there.

        The plain-JSON tree

        On whenever a broker is set, because any MQTT tool can read it: a retained JSON message at vm/<site>/<area>/<device>/state for each device, and vm/<site>/hermes/status, which the broker turns to offline when the bridge's connection is lost.

        Sparkplug B

        With "sparkplug": true, Hermes is also a Sparkplug B edge node, as SCADA hosts such as Ignition expect: its birth and death certificates (NBIRTH, NDEATH with bdSeq), a DBIRTH for each device, then DDATA with only what changed, and DDEATH when a device goes or stops answering. Metrics: Online, Power, Brightness, Volume, Playback and Kind.

        Commands from the broker

        Off by default ("acceptCommands": false): the bridge then listens only for a Rebirth request, at most every 10 seconds. Switched on, the broker may send simple commands only (power, dimming, colour, volume, play, pause, stop), never an address to play, a key, an app or a Home Assistant service, and always under each device's limits.

          A broker of your own: Mosquitto

          Listen on your home address only, with no anonymous users and an access list that lets only the VM user publish commands:

          listener 9001 192.168.1.20
protocol websockets
allow_anonymous false
password_file C:\mosquitto\passwords
acl_file C:\mosquitto\acl

          Limit: over ws:// the password and the messages cross the Wi-Fi in clear; wss:// fixes that. The bridge's README has the whole set-up.

          Law & safety

          What this page may and may not do

          It may look for devices, identify one at an address you type, add, remove and pair your devices, send them commands, give the bridge your Home Assistant token, tick Home Assistant entities, pair and revoke phones, and send an AI question you have confirmed.

          It may not read a key or a token, choose a port or the Home Assistant or broker address, aim the bridge outside your home connection, send raw protocol data, or switch on the phone remote, broker commands or the AI: those are yours, in the bridge's config file and its command line.

          Every jdpi.pages.dev page shares one web origin, so a script injected anywhere on the site could send what this page sends. That is an accepted limit, kept small: the site's security policy, device text shown only as text, every setup step waiting for a key press at your computer, Home Assistant entities off until ticked, and the rate limits and the volume ceiling.

          What is stored where

          This page keeps only whether you turned the bridge on, in this browser.
